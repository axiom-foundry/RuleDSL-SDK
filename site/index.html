Get Started How It Works

Deterministic by Contract

For the published DET corpus on the shipped v1.0.2 Windows and Linux x86_64 binaries, matching engine/ABI, bytecode, canonical input, and equivalent options produced byte-identical decision output. This is scenario evidence, not a formal proof over all rules and inputs.

Embedded Core

The core engine runs in process with no daemon, database, network service, or sidecar. Evaluation is parse-free on the hot path; measure latency and throughput on your own hardware and workload. The Python binding still loads the separate engine .dll/.so, the Workbench uses Tk, and MCP requires Python 3.10+ plus the MCP SDK.

Stable C ABI Design

Public structs use struct_size and reserved fields, with documented error codes. Shipped engine/SDK pairings are checked against the compatibility matrix; verify the intended pairing before an upgrade.

Language Bindings

C API at the core, with the Python 1.2.0 package, shipped C# wrapper, and desktop Workbench. The engine library remains the separate v1.0.2 binary bundle.

Self-Service Errors

Documented error codes provide actionable diagnostics on supported detection paths. The troubleshooting guide covers the public error contract and common integration failures.

Load Rules Without Recompiling the Host

The host can load newly verified bytecode without recompiling its application binary. Distribution, reload, and any atomic transition are host responsibilities. Changing the MCP 0.2 rule library requires restarting the MCP server.

How It Works

Define rules in RuleDSL — a simple, readable DSL for business decisions

2

Compile source into versioned bytecode, then verify its integrity and engine compatibility before evaluation.

3

Verify

Verify bytecode integrity and compatibility before loading into production.

4

Evaluate

Call the API with your data. Get a decision. ALLOW, DECLINE, REVIEW, or LIMIT.

rules.rule
rule high_risk {
  when amount > 1000
       and currency == "USD";
  then risk_score = 90,
       reason = "high_amount",
       decline;
}
evaluate.py
from ruledsl import RuleDSL

engine = RuleDSL("ruledsl_capi.dll")
rules = open("rules.rule").read()
bc = engine.compile(rules)

decision = engine.evaluate(bc, {
  "amount": 1200.0,
  "currency": "USD"
})
# decision.action == "DECLINE"

The agent selects a declared rule and supplies fields; the deterministic engine evaluates that invocation. An agent choosing the wrong rule or extracting the wrong fields is outside the engine's determinism guarantee.

Closed Three-Tool Surface

list_rules, evaluate_case, and engine_info. There is no write_rule, free-text compile, or tool that changes rules.

The Agent Invokes; the Engine Decides

Typed, fail-closed validation checks the declared MCP input before the selected rule reaches the engine. The resulting engine decision is based on the supplied invocation, not generated by the agent.

Explicit Runtime Boundary

The MCP extra requires Python 3.10+, the MCP SDK, and a separate v1.0.2 engine library. See the MCP quickstart for the supported setup and experimental contract.

Engine Robustness

Private engine CI exercises supported parser and bytecode-loader detection paths with coverage-guided fuzzing (libFuzzer under AddressSanitizer + UndefinedBehaviorSanitizer) and an adversarial corpus. The public SDK repository does not expose the engine source or every internal run, so this is vendor-reported release qualification, not independently reproducible public evidence. Detection coverage is not a blanket safety guarantee.

Internal Fuzz Qualification

Private engine CI uses coverage-guided fuzzing under ASan/UBSan with an adversarial corpus maintained in the engine repository. Individual internal runs and the engine source are not published here.

Defined Concurrency Boundary

Concurrent live calls on one compiler can be detected and return AX_ERR_CONCURRENT_COMPILER_USE. Destroying a compiler while a call is in flight is undefined behavior in the raw C API. The shipped Python and C# wrappers serialize native calls and protect close/Dispose. See the thread-safety model.

Locale Independence

Evaluation does not use locale, timezone, or wall-clock as inputs (determinism contract, DET-002). Cross-locale checks are part of internal engine release qualification; published claims remain limited to the committed DET corpus.

Tested Detection Paths

The adversarial corpus exercises malformed sources and supported tampered-bytecode rejection paths. SQL, markup, and CRLF are ordinary string data when encoding, schema, type, and size are valid; rejection claims apply to violations such as invalid encoding, NUL, schema/type mismatch, and limits. Malformed bytecode passed to evaluation and invalid pointer, ownership, or lifetime use may be undefined behavior. See the UB boundaries.
