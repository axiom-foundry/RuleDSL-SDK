# Pinned transitive closure for the MCP transport contract tests.
#
# Pinning `mcp` alone is not reproducible. The behaviour this server depends
# on lives partly in pydantic: argument-model construction, lax-mode coercion,
# and the extra="forbid" rebuild in server.py _attach_schemas. A pydantic minor
# release could change any of those without the mcp version moving at all, and
# CI would silently start verifying something else.
#
# Regenerate deliberately, never automatically:
#     python -m venv .venv && .venv/bin/pip install "mcp==<version>"
#     .venv/bin/pip freeze > Tools/ci/constraints-mcp-<version>.txt
#
# Windows-only entry (pywin32) is deliberately absent: CI runs on Linux and pip
# would fail on an unsatisfiable constraint. It is a platform dependency of the
# resolver's, not of the contract under test.
